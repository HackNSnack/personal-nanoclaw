# Claude Code & AI Tooling — Story

**Audience:** Mixed technical (developers, tech leads, managers)
**Duration:** ~30 minutes
**Tone:** Grounded & practical — no hype, just what works

## Opening Hook
Start with the noise. Everyone's seen the headlines — "AI will replace developers," "10x productivity overnight," endless Twitter threads about prompt engineering. Ask the audience: how much of that has actually changed your Monday morning? Probably not much. This talk is about what *actually* works when you cut through the hype.

## Context
AI coding tools exist on a spectrum — from autocomplete (Copilot) to autonomous agents (Claude Code, Cursor, etc.). Most people are either not using them at all, or using them superficially (chatbot Q&A). And here's the thing the hype won't tell you: AI doesn't solve everything. Full stop. It's not magic, it's not replacing you, and it won't 10x your output overnight. But — it *can* reduce real friction in your day-to-day work if you know where to point it. The gap between "I've heard of it" and "this is part of how I work" is where the real value lives. Getting there doesn't require a revolution — it requires small, deliberate steps.

## The Landscape — What's Out There
Brief, honest overview of the AI tooling space. Chat-based assistants, inline copilots, agentic tools like Claude Code. What each is good at, where each falls short. No ranking, no "best tool" — the point is understanding the categories so you can make informed choices.

## Claude Code — How It Actually Works
Zoom into Claude Code specifically. Not a feature list — show what a real workflow looks like. How it reads your codebase, how you give it context, how it proposes changes. Be equally honest about both sides. Where it genuinely helps: multi-file refactors, boilerplate, exploration of unfamiliar code, writing first drafts of tests. Where it falls short: it'll refactor 500 lines flawlessly, then hallucinate an API that doesn't exist. It can't make architecture decisions for you. It doesn't understand your business context. You still need to review everything it produces — and that's fine. The value isn't in blind trust, it's in faster iteration.

## Practical Workflows — The Small Wins
Concrete examples the audience can relate to. Things like: "I use it to write the first draft of tests," "I let it explore a codebase I've never seen," "I use it to refactor repetitive code." These aren't moonshots — they're Tuesday afternoon tasks. The key message: you don't need to rethink your entire process. Pick one friction point and try AI there.

## Turning Point
The shift isn't about AI doing your job. It's about *what you choose to spend your attention on*. When the tedious parts get faster, you spend more time on the hard, interesting problems — the ones that actually need a human. That's not hype. That's just a better workday.

## Closing
Don't try to change everything. Pick one thing — one task you did this week that felt repetitive or tedious. Try it with Claude Code next week. See if it helps. If it does, try another. That's it. No manifesto, no transformation roadmap. Just one thing this week.

---

**Key takeaways:**
1. AI tooling changes how we code — from writing everything to directing and reviewing
2. AI doesn't solve everything — but it reduces real friction when you know where to use it
3. Start small — try one thing this week and judge for yourself
